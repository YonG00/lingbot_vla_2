# CUDA缓存清理：观测与复用对照

当前实现默认保留清理行为，复用模式尚未GPU验收，不能宣称已有提速收益。
代码只在本地修改，未部署到在跑训练机，不热改、不重启现有训练。

## 开关与范围

| 开关 | 默认 | 作用 |
|---|---|---|
| `AL_CUDA_CACHE_POLICY` | `clear` | `clear`维持清理；`reuse`跳过评测入口/周期HF入口的CUDA空闲块释放 |
| `AL_CUDA_CACHE_TRACE` | `0` | `1`记录调用墙钟、GC耗时、CUDA清理调用耗时和前后显存数据 |

二者在模块首次导入时读取；修改必须重启进程。启动器的`AL_*`环境透传适用。
`reuse`仍执行原有GC；一般清理、逐片加载、训练中定期清理、周期DCP、
收尾和评测OOM异常处理中的强制`empty_cache()`均保留。
不碰模型、优化器、采样、RNG、评测KV/视觉网格缓存恢复，也不重置显存峰值统计。

诊断不额外同步GPU。`cuda_seconds`是调用墙钟，可能包含等待前序GPU工作，
不能把它当成纯分配器耗时，更不能把省略调用时长直接当成训练提速。
诊断/日志失败不阻止既有清理；实际清理异常保持原有异常传播。

## 空闲GPU对照步骤

训练运行期间禁做GPU测试（AGENTS.md §1.9）。当前只完成CPU契约验证。
等现有训练自然结束后，用同一份固定HF与池、同一份数据/config/seed，
同一条经确认的验收命令，分别启动两个新输出目录；除缓存策略和输出路径外
不改变参数。A用`AL_CUDA_CACHE_POLICY=clear AL_CUDA_CACHE_TRACE=1`，
B用`AL_CUDA_CACHE_POLICY=reuse AL_CUDA_CACHE_TRACE=1`，保存为`clear.log`/`reuse.log`。
必须覆盖训练→评测→恢复训练→周期HF→恢复训练；仅测清理函数或只测收尾不能验收。
测试应使用已批准的短程配置，不替换正式训练的`SAVE_EVERY=220`等参数。
机器侧长测试用本地写脚本→scp→`setsid nohup`后台运行，另起调用读日志。

先运行一次A/B，反向B/A重复，以降低文件页缓存/编译预热/磁盘波动的顺序影响。
前期加载与预热单独查看；不同步数、评测次数或存档次数的日志不可直接比较总耗时。

对照日志的CPU汇总命令（包目录执行）：

```bash
python tools/auto_learning_pipeline/al_cache_profile.py --clear-log clear.log --reuse-log reuse.log
```

汇总包含：唯一训练步数/步号范围/步时中位数/步时总和/末步loss、
评测次数与评测日志耗时合计、日志首末时间跨度、OOM日志行数、
分阶段清理次数/GC耗时/清理调用耗时/观测点最大reserved。
`max_observed_reserved_bytes`仅为观测点最大值，**不是整个运行的显存峰值**；
完整峰值须结合外部nvidia-smi采样和既有GPU验收监控。
StepTime求和也**不是完整墙钟**，须与日志跨度及存档起止记录一起看。

验收须同时满足：同工作量整段墙钟改善；无新增OOM/批大小降级；
评测数值、恢复审计与后续训练正常；周期HF完整且只导出一次。
只看末步loss不能证明训练数值等价，要用既有精度/评测验收入口核对。
未通过则恢复`clear`；停止测试进程也必须事先获准，不操作正式训练进程。

## 10-14重复存档成本证据

当前运行日志的额外HF导出起止（精度为日志秒级）：

| 导出 | 起止 | 耗时 |
|---|---|---:|
| 4400第二次 | 13:25:03→13:26:28 | 85s |
| 4650额外 | 13:40:16→13:41:10 | 54s |
| 4850额外 | 13:55:26→13:56:21 | 55s |
| 5100额外 | 14:14:10→14:15:05 | 55s |

合计249s（4分9秒），均值62.25s。每220步多一次HF的调度去重后，
按这个样本均值估算，每1000步可少282.95s（4.72分钟）。
4300→20000有71个220倍数，若完整区间应用去重并保持当前磁盘耗时，
预计少4419.75s（73.66分钟）。这是推算，**不是补丁已运行后的实测节省**；
未计GC、池导出/磁盘检查开销，也未计独立的收尾重复HF。
缓存复用的收益不包含在上述数字中，仍待GPU实测。
