# 相对输入状态的动作表示：后续实验思路

## 目的

评估将50帧动作块表示为相对输入状态的位移，是否比直接预测绝对关节目标更容易学习精细接近与夹取动作。它是动作参数化实验，不是力监督。

## 当前数据口径

RoboTwin 的 `observation.state` 来自关节 drive target；当前数据没有逐帧保存实际关节 qpos、qvel 或接触力。闭环评测也把该状态向量传给策略。虽然机器人对象另有读取实际 qpos 的函数，但现有训练集不能从 `observation.state` 还原跟踪误差。

对当前训练样本计算：

```text
relative_action[t+k] = action[t+k] - observation.state[t]
```

得到的是未来 drive target 相对起始 drive target 的变化。它不是期望位置减实测当前位置，因此不能解释成 PD 误差或夹爪力。

## 代码现状与候选实验

`FeatureTransform` 已支持 `subtract_state=true`：训练时从 chunk 中每个动作减去锚点状态，推理解码时加回锚点状态；RoboTwin 当前配置对 arm 和 effector 均为 `false`。从 checkpoint 续训时不能只切换配置，需要使用独立 run 和匹配的归一化统计重新训练。

若预测值与真值都减去同一锚点状态，再用同一物理尺度计算 MSE/Huber，差值会抵消，监督强度不会增加。实际实验的差别来自特征表示、归一化统计以及模型在归一化空间里的优化尺度，而不是标签里出现了新信息。

建议以独立、单变量对照验证：保持模型起点、数据、训练步数、窗口采样、低噪 FM、EE 权重和评测噪声不变，只对 `action.arm.position` 开启相对表示。若要测试夹爪相对表示，另开实验，不与 arm 表示同时切换。对比原始 GMSE、整轨迹 EE 指标、抓取阶段 EE 指标以及同一场景集的闭环抓取成功率；闭环成功率是最终判据。

## 与力监督的边界

固定 PD 增益下，`Kp * (q_des - q_actual)` 可作为比例控制项的代理，但必须取得与目标时间对齐的实际 qpos。完整控制努力还需要速度误差、增益、饱和和驱动器动态；物体接触力还需仿真接触或力传感信号。当前训练数据缺这些字段，所以现阶段不构造“力标签”。

后续若采集新数据，应单独保存 drive target、actual qpos/qvel、驱动力或接触力，并先核对时钟对齐、单位、左右臂关节映射和与实际接触的相关性，再设计辅助 loss。
